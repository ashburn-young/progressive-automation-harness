    What this solution is
    
      
    
        The Progressive Automation Harness takes a manual workflow you
        describe in plain language, grounds it into an ordered plan with an LLM,
        runs it with you approving each step, and compiles a reusable
        Skill that progressively takes over the steps you keep approving,
        until it can run them without you. It runs offline for demos, live against
        Azure AI Foundry, and is deployed to Azure Container Apps with Cosmos DB.
      
    
    
    

    
    
      
    
        
    Harness
    
        
    The scaffolding that interviews you, runs an agent under human
        oversight, and harvests every approval as training signal. Like a test or
        climbing harness, it exists to hold a task safely until it can stand on its
        own. It is the part you eventually remove.
    
      
    
      
    
        
    Skill
    
        
    The learned, versioned artifact the harness produces
        (skills/<task>.json). Per step it stores the
        human-approved actions and an earned maturity level. It is both the
        dataset (labelled good actions) and the compiled program (it can draft the
        next action once mature). It is the part that remains.

    Skills are portable across models
    
      
    A skill is plain, model-agnostic JSON with no OpenAI or Azure coupling: the workflow, its inputs, and the human-approved action per step. Any LLM can run it, two ways:
    
      
    
        
    Replay. For a mastered step the skill returns the approved action with no LLM call at all. Fully model-independent and deterministic.
    
        
    Prime. The approved examples are handed to any LLM (Claude, GPT, Gemini, local) as few-shot context. Only the model provider swaps; the skill does not.
    
      
    
      
    The Prompt button on a skill exports a ready-to-paste prompt you can drop straight into Claude or any model. Only the harness's LLM provider is Azure-specific; the skill artifact you keep is not.
    
    
    

    
    
      
    The skill lifecycle
    
      
    A skill is a governed asset. Its maturity (how much it does on its own) climbs as you approve, while its lifecycle status (how it is managed) moves through explicit, gated stages. Drift or failures pull a live skill back under supervision; versions are snapshotted on every publish so you can roll back.
    
      
    flowchart LR
  A["Draft
    authored / interviewed"] --> B["In training
    approvals accrue, maturity climbs"]
  B --> C["Candidate
    mature + no regressions"]
  C -->|"promote (gate)"| D["Active
    published, runnable"]
  D --> E["Monitored
    telemetry + drift"]
  E -->|"drift / failures"| F["Needs attention
    demoted to supervision"]
  F --> B
  D -->|"superseded"| G["Deprecated"]
  G --> H["Retired / archived"]
  G -.->|"reactivate"| D
      
    
      
    The publish gate requires the skill to reach DETERMINISTIC with no rejected or failed steps; execution drift flips a live skill to Needs attention automatically. Manage all of this per skill from the Library → Lifecycle panel: promote, certify, deprecate, retire, reactivate, and roll back to any prior version.
    
    
    

    
    
      
    Skills-based vs. agentic architecture
    
      
    This is an agentic system — it runs a reason → act → observe loop — but its product is a skill, not an agent. It treats the agent as a factory that distills itself into durable, deterministic skills. The question is where the intelligence ends up living: invoked fresh from the model every run, or extracted into a reusable, governed asset.
    
      
    
        
    DimensionClassic "agentic" solutionThis skills-based harness
    
        
    Where intelligence livesIn the model + prompt, invoked fresh every runExtracted into a compiled artifact; the LLM is only called for cold / novel steps
    
        
    DeterminismNon-deterministic; same input can take different pathsMastered steps replay byte-for-byte, auditable
    
        
    How it improvesChange the prompt / model / fine-tuneHuman approvals provably graduate steps up a maturity ladder
    
        
    Human roleTrust assumed up front; review after, or guardrails onlyHuman in the loop by default; supervision decreases as trust is earned, per step
    
        
    Cost / latency~Constant LLM cost foreverDecays toward zero as skills mature
    
        
    PortabilityBound to its framework / model / runtimeA model-agnostic artifact any LLM can replay or prime on
    
        
    DriftSilent when the model updatesDrift monitoring + demote-on-failure pulls a step back under supervision
    
      
    
      
    The mental model: a pure agent is a brilliant contractor you re-hire and re-brief for every job. A skills-based harness supervises that contractor a few times, writes down the vetted procedure, and after enough consistent runs the procedure runs itself — the LLM is only called back for genuinely new situations. Agentic is "intelligence as a service, per call"; the skill approach is "intelligence amortized into a reusable asset."

    Usage & the decay dynamic
    
          
      
            
    • The main variable is model tokens on immature steps; mastered steps replay with no LLM call.
      • 
            
    • Content Safety per action (~$0.75/1,000), embeddings ~free, Cosmos RUs pennies, Log Analytics per GB.
      • 
            
    • Fabric capacity (F-SKU) only if you run real pipelines; extra model deployments add ~$0 idle (pay-per-token).
      • 
            
    • Per-run cost is highest during learning and trends toward near-zero as steps graduate — unlike an agent that pays full token cost every run forever.

    Why an enterprise would use this
    
      
    
        
    Starts where the work is. An employee describes a task they already do; it automates incrementally as trust is earned. Adoption is bottom-up and low-risk.
    
        
    Humans in control by default. Nothing runs unattended until approved consistently, and any step can be pinned to always require a human.
    
        
    Captures tacit knowledge. The skill artifact is a portable, auditable record of how a task is done, independent of the individual.
    
        
    Governed infrastructure. Managed identity, RBAC, private networking, Key Vault, and App Insights, the same controls enterprises already mandate.
    
        
    Orchestrator-agnostic. The same Reason, Act, Observe loop works with LangGraph or Semantic Kernel; the harness and skill are the durable parts.
    
        
    Automates the long tail. Most value is locked in thousands of small, undocumented workflows too minor for a classic automation project.
